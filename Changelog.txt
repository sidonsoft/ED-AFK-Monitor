========================
ED AFK Monitor Changelog
========================

Fork: dashboard renders readable panels, not JSON walls (2026-10-26)
------------------------------------------------
- The --dashboard page now shows session/total stat tables, a mission
  spread table, and a wing panel (combined totals, sources, staleness
  and relay warnings in amber) instead of two raw JSON blobs.
- /live.json and /missions.json keep the exact same payloads; unknown
  mission payload shapes still fall back to the JSON dump.
- No dependencies: standard-library http.server plus plain vanilla JS.
- Validation: 211 tests passed.

Fork: staleness reaches the offline --missions --wing view (2026-10-26)
------------------------------------------------
- wing_relay.stale_notes() is now the single freshness check: summaries,
  the [w] hotkey, the dashboard AND --missions --wing (plain or --json)
  all flag quiet wingmate ledgers identically.
- Validation: 211 tests passed.

Fork: stale wingmate detection (2026-10-26)
------------------------------------------------
- A shared ledger nobody saved for >24h now flags itself in the wing-view
  warnings: 'mate: no updates for 48h - counts may be stale' - the dead
  wingmate's finished missions no longer masquerade as current progress.
- Ledgers carry their 'updated' timestamp into spread()/merge results,
  so folder-copied AND relay-fetched ledgers are both checked; the flag
  shows in summaries, the [w] hotkey and the dashboard wing_view.
- Validation: 210 tests passed.

Fork: WatchdogSeconds - tunable time-based check cadence (2026-10-26)
------------------------------------------------
- '[Settings] WatchdogSeconds = 60': idle watchdog now configurable -
  kill-rate/no-kill warnings, mission expiry alerts and PushEvery relay
  pushes all fire on it; lower it for faster reaction, CI runs it at 5
  and the live scenario went from 60s to ~10s (suite back to ~40s).
- Watchdog failures now log as 'Watchdog error' - the old 'Kill rate
  tracking error' label misdirected when the block grew (it hid a
  NameError behind a plausible-sounding message).
- Validation: 208 tests passed.

Fork: mid-session relay pushes ([Wing] PushEvery) + startup-session fix (2026-10-26)
------------------------------------------------
- '[Wing] PushEvery = N': wingmates now get ledger updates while you fly,
  not just when you stop; piggybacks the ~1/min watchdog, exit always pushes.
- Fixed: --resetsession set deploytime to None (no journal event processed
  yet), permanently disarming every time-based watchdog - kill-rate/no-kill
  warnings, mission expiry alerts, live status and now relay pushes. Session
  start falls back to 'now'; sessionend guards a still-empty session.
- Live relay scenario proves the mid-session PUT lands before shutdown
  (it waits out the real ~60s watchdog cadence; suite time 34s -> 92s).
- Validation: 208 tests passed.

Fork: dashboard missions.json gains a wing_view section (2026-10-26)
------------------------------------------------
- With SummaryMissions = 3 and wing sources configured, the dashboard's
  /missions.json now embeds 'wing_view': combined totals, every source
  ledger name and any relay errors - same numbers as summaries, hotkey
  and Discord embeds.
- wing_view() moved ahead of dashboard startup so the provider closure
  never races the definitions; each URL times out on its own.
- The live-relay scenario now also serves the dashboard on :18931 and
  asserts its wing_view payload end-to-end (first dashboard scenario).
- Validation: 206 tests passed.

Fork: Discord mission embed carries the wing view (2026-10-26)
------------------------------------------------
- With DiscordEmbeds on, summaries were the one place the wing view never
  reached Discord; the mission embed now has a 'Wing view' field (combined
  totals across local + shared ledgers) beside Projection.
- One wing_view() pass per summary feeds embed, terminal and Telegram -
  the relay is fetched once, not per output channel.
- docs/wing-missions.md gained a full 'Sharing ledgers with wingmates'
  section (shared folder, relay flags, [Wing] config automation).
- Validation: 206 tests passed.

Fork: wing view hotkey [w] (2026-10-26)
------------------------------------------------
- Press 'w' while the monitor runs: combined wing view (local + copied
  wing-folder ledgers + every configured relay), per-source breakdown and
  relay errors inline; empty wing data says so via 'nothing to report'.
- Summary and hotkey share one wing_view() pipeline; preset maps gained a
  'wing' command ('status,missions,mute,wing' default, or wing=KEY custom).
- Validation: 206 tests passed.

Fork: multiple wingmates per summary (Wing relay follow-ups) (2026-10-26)
------------------------------------------------
- '[Wing] FetchURL' is now a list: several wingmate ledgers merge into one
  wing view; a fully or partly down relay still folds in what answered.
- '--set/--save Wing.PushURL=... / Wing.FetchURL=[...]' now reach the Wing
  section too (typed like every other setting).
- Validation: 204 tests passed.

Fork: hands-free wing relay for the live monitor (2026-10-26)
------------------------------------------------
- '[Wing] PushURL' in the config: the monitor pushes its ledger to the relay
  every time it stops (normal exit or crash path), no extra commands.
- '[Wing] FetchURL': the fetched wingmate ledger folds into live and final
  summaries at SummaryMissions = 3; a down relay warns once, not per summary.
- Integration scenario drives the real monitor against a live local relay.
- Validation: 202 tests passed.

Fork: wing ledger relay over HTTP (2026-10-26)
------------------------------------------------
- '--wing-push <base_url>' uploads local mission ledgers (HTTP PUT to
  {base}/{file}); any PUT-capable host works - bucket, nginx dav, tiny relay.
- '--wing-url <url>' (repeatable) fetches wingmate ledgers back into the
  '--missions --wing' combined view; fetch failures warn, never crash.
- Completes roadmap item 13 (shared folders still work unchanged).
- Validation: 201 tests passed.

Fork: config persistence with --save (2026-10-26)
------------------------------------------------
- '--save Section.Key=value' writes typed values back into afk_monitor.toml
  and applies them to the current run, like '--set' did for one run only.
- New dependency-free editor keeps comments and layout intact (inline
  '# ...' notes survive value edits); writes atomically via temp file.
- Completes roadmap item 17; no tomlkit dependency needed.
- Validation: 195 tests passed.

Fork: main() wrapper + typed runtime state (2026-10-26)
------------------------------------------------
- afk_monitor.py top-level flow now runs inside main(); module import no
  longer executes the monitor pipeline.
- All module-level globals removed: live-delivery generation counters and
  the active journal file live on the Tracking object (monitor_state.py).
- Tests can extract production functions even when nested in main()
  (ast.walk + dedented source segments in the loader).
- Validation: 188 tests passed.

Fork: multi-instance watch mode (2026-10-26)
------------------------------------------------
- '--instance label=journal_folder' (repeatable) supervises one monitor per
  journal folder - each keeps its own profile, ledgers, history and outbox,
  so multi-CMDR rigs or alpha+live setups run under a single command.
- Crashed instances restart (bounded); one Ctrl+C stops everything cleanly.
- '--test' now skips the GitHub update check, staying fully offline.
- Validation: 188 tests passed.

Fork: terminal hotkeys (2026-10-26)
------------------------------------------------
- Press [s] for the current status line, [m] for the mission spread and [u] to
  mute/unmute remote alerts for 10 minutes, while the monitor runs in a focused
  terminal. Keybindings are customisable in code ('hotkeys.py' presets).
- '--no-hotkeys' disables the watcher entirely (services and piped runs stay
  untouched: the watcher only engages on interactive terminals).
- Validation: 182 tests passed.

Fork: service mode guide (2026-10-26)
------------------------------------------------
- New docs/service-mode.md: systemd user service, macOS launchd agent, Windows
  Task Scheduler keep-alive and Docker guidance for always-on headless rigs.
- Validation: 175 tests passed.

Fork: typed session-state core (2026-10-26)
------------------------------------------------
- Stats, Tracking, per_hour, time_format and num_format now live in an
  importable 'monitor_state' module with type hints and attach()-based
  dependency injection, unit-testable without booting the monitor script.
- Validation: 175 tests passed.

Fork: wing-shared mission ledgers (2026-10-26)
------------------------------------------------
- '--missions --wing' merges wingmate ledgers (mission_ledger/wing/*.json,
  e.g. synced via Dropbox/Syncthing) with the local stack into one wing view.
- SummaryMissions = 3 adds the combined wing line to live and exit summaries.
- Validation: 168 tests passed.

Fork: local web dashboard (2026-10-26)
------------------------------------------------
- '--dashboard <port>' serves a read-only localhost page with live session
  totals and the mission spread JSON; no extra packages needed.
- '--dashboard-token' protects share links (?token=...), '--dashboard-host
  0.0.0.0' exposes it to the LAN for wingmates without Discord.
- Validation: 164 tests passed.

Fork: session exports and packaging (2026-10-26)
------------------------------------------------
- '--history --export file.(json|csv|png)' writes portable session data or a
  rendered recap card; '--history --share' prints a compact copy-paste recap.
- Packaging: pyproject metadata with optional extras (discord-webhook, pillow),
  requirements.txt, Dockerfile for headless rigs, and PyInstaller release
  builds on GitHub Actions for Windows/Linux/macOS.
- Validation: 160 tests passed.

Fork: journal drift checks and command-line config overrides (2026-10-26)
------------------------------------------------
- On exit, the monitor now reports journal event types it does not handle
  ('Journal drift check'), so game updates surface as visible notices
  instead of silently doing nothing; full counts available with --debug.
- New '--set Section.Key=value' argument overrides any config setting for
  one run (type-checked, e.g. --set Discord.Timestamp=false).
- Validation: 150 tests passed.

Fork: ntfy, generic webhooks and local alert sounds (2026-10-26)
------------------------------------------------
- New 'Ntfy' section: push alerts to phones/desktops via ntfy (priority high).
- New 'Webhook' section: generic JSON webhook ({'text': message}) for
  Slack-style endpoints and Home Assistant webhooks; both persist to the
  notification outbox like other channels.
- 'AlertSound' setting plays a local sound on level-3 alerts: terminal
  bell on any platform, 'beep' or a .wav file on Windows (default: none).
- Validation: 141 tests passed.

Fork: Discord embeds for mission reports (2026-10-26)
------------------------------------------------
- Session/live summaries send the mission spread as a Discord embed with
  per-faction progress fields, reward totals and the projection line.
  Plain-text mission blocks remain available via 'DiscordEmbeds = false'.
- Validation: 133 tests passed.

Fork: mission kill attribution accuracy (2026-10-26)
------------------------------------------------
- Combat bond events (FactionKillBond) now advance mission stacks too, and
  events carrying an exact MissionID credit that specific mission.
- Kills no longer credit missions whose destination system is known and
  differs from the system the kill happened in.
- Validation: 128 tests passed.

Fork: session history (2026-10-26)
------------------------------------------------
- Each monitor run with logged activity is saved to a per-profile
  session database when the monitor stops; use --history (with --json
  for machine-readable output) to print per-run duration, kills and
  rate, bounty credits and rate, merits and mission progress with totals.
- 'HistoryDays' setting controls retention (Default: 90).
- Validation: 125 tests passed.

Fork: mission value projections (2026-10-26)
------------------------------------------------
- Session and live summaries now include a projection line: mission
  cr/hour at the current kill rate, estimated time until the stack
  completes, and credits ready to turn in.
- Validation: 119 tests passed.

Fork: mission expiry alarms (2026-10-26)
------------------------------------------------
- Warn when an unfinished massacre mission expires within WarnMissionExpiry
  minutes (Default: 15, 0 disables); already-expired-but-open missions are
  reported once per game session. Log level 'MissionExpiry' (Default: 3).
- Validation: 116 tests passed.

Fork: roadmap 'Now' sprint (2026-10-26)
------------------------------------------------
- Per-channel message length policy: over-long messages are split at line
  boundaries instead of being dropped by Discord (2000) or Telegram (4096).
  Telegram chunking moved into the notification dispatcher.
- New 'Repo' setting selects which GitHub repository announces updates;
  defaults to this fork so fork users see fork releases. The check now
  runs after config load.
- New 'ShipsFile' setting plus ships.json data file: the 'easy'/'hard'
  ship pools can be edited (or replaced) without code changes; invalid
  files fall back to the built-in pools with a warning.
- New 'WebhookAvatarURL' setting overrides the Discord webhook avatar.
- Fuel reports no longer produce warnings when no fuel burned between samples.
- Journal lines without VictimFaction (older game versions) no longer warn.
- Validation: 112 tests passed (new ship pool and message-split coverage).

Fork: wing mission stack test build (2026-10-26)
------------------------------------------------
- Add issuer stacks, estimated kill progress, remaining kills and stack differences.
- Count same-issuer missions in sequence and different issuers in parallel.
- Add total/shareable rewards, confirmed turn-in value, averages and kill ratio.
- Record and recover mission origins and destination systems from journals.
- Expand saved mission reports and JSON; bound Discord reports and remove duplicates.
- Preserve existing saved estimates and settings when upgrading.
- Add guides for stack fields, accuracy, imports, testing, updates and rollback.
- Validation: 102 tests passed on the gaming PC and six CI platform/Python jobs passed.
